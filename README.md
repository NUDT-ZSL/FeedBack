# 离线战斗结算追溯台

这是一个零依赖、可离线运行的浏览器战斗规则原型。直接双击打开 `index.html`，或在目录中运行 `npm test` 执行自动验证。

## 能力

- 载入参战单位、技能、状态效果、规则与有序行动。
- 每条行动依次记录：命中判定、伤害/治疗数值、阶段修正、护盾吸收、效果施加、状态变化。
- 每个回合结束时按确定顺序处理持续伤害、持续治疗、持续回合衰减与到期移除。
- 状态支持 `replace`（覆盖）、`refresh`（刷新）、`stack`（叠加）三种规则；护盾记录剩余吸收量。
- 缺失效果、缺失规则和规则循环依赖会在问题面板标出，并从数值合成中跳过。
- 修改规则或行动后，按最早受影响行动复用检查点续算；“全量重算比对”会验证最终状态与从头计算完全一致。

## 输入结构

- `config.finalTurnSettlement`：是否结算最后一个行动回合，默认 `true`。
- `effects`：状态定义。常用 `kind` 为 `outgoingIncrease`、`vulnerable`、`reduction`、`shield`、`damageOverTime`、`healOverTime`。
- `rules`：数值规则。`stage` 可为 `outgoing`、`vulnerability`、`reduction`、`shield`；前三个阶段的 `value` 是百分比，护盾阶段的 `value` 是一次性固定吸收量。`requiredEffects` 和 `requiredRules` 构成可追溯依赖，`priority` 决定同阶段来源顺序。
- `skills.hitRate` 与 `basePower`：命中率和基础伤害；`effects` 声明命中后施加的状态。
- `actions`：必须按 `turn` 非递减排列。

## 增量结算

系统在每个行动后保存不可变状态快照。规则、效果或技能变化会沿引用关系定位第一次可能受影响的行动；行动增删改定位到第一个不同的行动位置。续算只执行该位置之后的回合事件，再把事件与快照拼回完整时间线。

界面默认只续算。需要审计时点击“全量重算比对”，界面会同时显示全量哈希与状态深比较结果。

## 离线说明

项目没有第三方运行时依赖、字体、图片、CDN、网络请求或分析服务。浏览器只读取当前目录中的 HTML/CSS/JS 文件；JSON 导入与导出也通过浏览器本地文件 API 和内存对象完成。
