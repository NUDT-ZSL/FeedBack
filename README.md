# 远古药谷 · 采药炼丹

## 离线确定性验证（无需浏览器、无需网络）

链路「地形生成 → 草药采集 → 炼丹炉投料 → 成丹」的全部判定逻辑收敛在
`src/core/`（纯 TypeScript，不依赖 THREE/DOM），浏览器端游戏类委托同一实现：

- `src/core/random.ts` — 可注入随机源；`createSeededRandom(seed)` 保证同种子同序列
- `src/core/terrain.ts` — 地形高度/溪流纯函数与草药落点放置（约束 + 数量保证 + 兜底扫描）
- `src/core/herbs.ts` — 草药数据生成（类型、药性由注入随机源决定）
- `src/core/furnace.ts` — `FurnaceCore`：投料判定、炉体颜色、炼制时间推进、丹药结论
- `src/core/rules.ts` — 进入炼丹的数量门槛与药篓投料规则
- `src/core/session.ts` — `AlchemySession`：无渲染端到端会话，`update(deltaTime)` 注入时间

### 运行

```bash
npm test          # 退出码 0 = 全部通过；非 0 = 有失败（适合 CI 批量执行）
```

### 覆盖的风险点

1. 地形：200 个种子逐株校验「距溪流>3、中心半径<size*0.4、高度<5」；
   随机源恒被边界拒绝时进入确定性兜底扫描，草药数量始终恰好 25；
   全区域无合法点时抛出明确错误而非静默少放。
2. 投料：同元素、异元素、空槽重复投料、非法槽位、草药不在药篓、
   数量不足（<5）进入炼丹被拒绝；120 种投料顺序全排列校验炉体颜色与
   槽位状态一致；炉体颜色与 `THREE.Color` 管线逐位对齐（32 种组合）。
3. 成丹：品质/匹配度/名称/ID 只由槽位元素构成决定（FNV-1a 哈希命名），
   不含随机数与墙钟时间；不同投料顺序、不同时间步长（0.1×20 与 0.4×5）
   结论逐字段一致；端到端两次同种子运行结果逐字节一致。
