# 协作编辑协调工具

本地启动的协作编辑合并与变更确认工具。载入带章节层级的文档和多位
协作者的编辑记录后，系统把编辑按目标段落分组合并，识别重叠/冲突/
依赖关系，用户可逐条接受、拒绝或手动调整，并实时看到联动更新与
最终文档。

## 启动

```
python server.py
```

然后浏览器打开 http://127.0.0.1:8000 （可用 `--port` 改端口）。
仅依赖 Python 3 标准库，无需安装第三方包。

## 数据格式

页面可加载一个 JSON 文件，包含两个字段：

- `document`：章节树，`sections` 支持嵌套；每个章节有 `title` 和
  `paragraphs`（段落含稳定 `id` 与 `text`）。见 `sample/document.json`。
- `edits`：编辑记录数组，字段：
  - `id` / `author` / `note`：标识、协作者、备注
  - `target`：目标段落 id
  - `type`：`replace`（整段替换）、`delete`（删除段落）、
    `append`（段尾追加）、`insert_after`（段后新增段落）
  - `content`：新内容（删除类型可省略）
  - `depends_on`：依赖的其他编辑 id，依赖被拒绝/失效时本条自动失效

## 合并与确认规则

1. 同一目标段落的编辑归为一组；两个及以上 `replace`/`delete` 落在
   同一段落本体时判定为冲突，冲突预览保留原文并列出来源，不覆盖。
2. `append`、`insert_after` 等互不覆盖的编辑可组合合并。
3. 接受某条本体编辑后，与其冲突的待确认编辑自动标记“已被取代”并
   说明原因，段落内不会残留互相矛盾的内容。
4. 接受删除后，同段落其余编辑标记“已失效：目标段落已被删除”。
5. 依赖的编辑被拒绝/失效/取代时，依赖方递归标记失效并给出原因。
6. 可对任一处手动调整：手动文本覆盖整组，组内编辑标记为被覆盖；
7. “最终文档”只应用已接受与手动调整的内容；右栏同时列出仍未解决
   的冲突与待确认编辑。

## 文件说明

- `merge.py`：合并引擎（状态派生、冲突识别、文档生成）
- `server.py`：本地 HTTP 服务与 JSON API
- `static/`：单页前端（章节树、改动确认、最终文档）
- `sample/`：示例文档与编辑记录（含冲突、依赖、删除失效等场景）
- `test_merge.py`：引擎规则测试，运行 `python test_merge.py`
