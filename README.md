# 专注会话恢复工作台

一套**纯本地、离线可用**的专注会话恢复工具：把阶段时间线、实际计入的工作时长、剩余额度和继续进入的位置摊开在同一界面里。无需构建、无需联网、无需安装依赖。

## 启动

直接用浏览器打开 `index.html` 即可（双击即可，`file://` 协议下也能正常运行）。
首次打开会载入一份示例会话，覆盖归并、冲突、越界裁剪、已消解等典型情形，方便直接体验。

数据保存在浏览器 `localStorage`，刷新不丢失；点「恢复示例数据」可重置。

## 运行测试

```bash
npm test        # 等价于 node --test（Node ≥ 18）
```

## 功能与需求对照

| 需求 | 实现 |
| --- | --- |
| 1. 维护会话与阶段 | 左侧「工作阶段」编辑顺序/名称/预算；时长非正、顺序重复、缺名称一律拒绝并在日志中指出第几个阶段 |
| 2. 打断记录与归并 | 报告带来源、区间、消解状态；零长/起止颠倒拒绝；重叠或相接区间按 (起点, 终点, 标识) 排序扫描归并为互不重叠的净打断区间 |
| 3. 推导计入与恢复位置 | 工作钟模型：净打断从墙钟扣除，阶段按顺序占满工作钟；输出各阶段计入/剩余、状态与「继续进入」横幅；纯函数 + 确定性排序，同批记录重复推导完全一致 |
| 4. 事后补报 | 补报后回填区间并重推；越界部分裁掉并在净区间列表与日志中说明；差分报告扣减/平移/未受影响阶段 |
| 5. 重复计入扣减 | 净区间与已计入片段交叠部分自动扣减，日志注明扣减来源（打断标识 + 来源）；「计入 + 剩余 = 预算」守恒校验常驻显示 |
| 6. 矛盾报告冲突 | 同一打断的多来源报告区间或消解结论矛盾时，双方全部保留、生成可读冲突记录、该打断暂不纳入推导（不静默择一）；用户点「采纳此来源」后消解 |
| 7. 界面 | 阶段时间线（计入/剩余/净打断/冲突标记/当前时刻）、净打断区间列表、各阶段计入与剩余表、冲突卡片、事件日志；任何变更立即重算并刷新 |

## 文件结构

```
index.html          界面骨架
styles.css          样式
src/engine.js       纯函数推导引擎（浏览器挂 window.FocusEngine，Node 走 module.exports）
src/app.js          界面层：状态、渲染、交互（IIFE，无构建依赖）
tests/engine.test.js  引擎测试（node:test，18 个用例）
```

## 核心模型：工作钟

会话墙钟区间 `[startMin, nowMin)` 扣除净打断区间后构成「工作钟」。阶段按顺序依次
占满工作钟（阶段 k 占 `[B_{k-1}, B_k)`，B 为预算累计），阶段计入时长即其工作钟区间
与 `[0, 总工作时长)` 的交叠。由此天然保证：

- 同一墙钟时刻不会被计两次（打断区间不属于工作钟）；
- 计入 + 剩余 = 预算（逐阶段守恒）；
- 补报打断只会把总工作时长缩短，扣减确定性落在当前工作 frontier 阶段，
  已完成的更早阶段不受影响。
