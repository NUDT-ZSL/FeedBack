# 多角色权限收敛工作台

一个零第三方依赖、可离线运行的全栈演示应用，用于验收多页面授权快照、权限收窄、冲突保留和未确认操作阻断。

## 启动

```powershell
npm start
```

然后打开：

```text
http://localhost:8080
```

不需要 `npm install`，运行环境只要求 Node.js 18+。也可以用 `$env:PORT=9090; node server.js` 指定端口。

## 自动验收

```powershell
npm test
```

测试覆盖：

- 成员标识重复、未登记角色引用及具体位置；
- 授权范围继承闭包、继承成环、不存在范围及涉及链条；
- 每个页面独立保存生效时刻、角色、页面、操作、范围快照；
- 权限变更只让权限签名变化的页面生成新快照；
- 范围收窄后已加载数据保留、标记失效并展示依据；
- 多来源矛盾角色/范围全部保留，冲突未裁定前不生效，裁定后收敛；
- 旧权限下已发起但未确认的操作在收窄后保留证据并变为 `blocked-pending`，不能确认生效。

## 建议手工验收路径

1. 启动后已有李雯的两个客户页面，第二个页面预置了“已发起、未确认”的审批。
2. 在“调整角色”中将李雯改为“只读成员”，两个李雯页面生成修订 2，审批操作变为阻断待处理；其他成员页面不变化。
3. 尝试确认该操作，服务端返回 `ACTION_REVOKED`，界面仍保留原始证据、旧快照和收窄版本。
4. 重启后在“调整授权范围”中把李雯从 `scope-shanghai` 改为 `scope-budget`，客户事项保留在页面中但标为 `SCOPE_NARROWED`。
5. 点击“注入范围冲突来源”，可看到 HR 与审计两条来源；未裁定前成员访问被阻塞。选择其中一方后权限才生效，双方授权仍保留在成员来源中。
6. 在“维护继承关系”中把上海改为包含华东，会得到精确的环：`scope-east -> scope-shanghai -> scope-east`；把华东改成包含不存在的 ID，会得到对应 `includes[0]` 位置和链条。
7. 使用“维护角色页面/操作”收窄正在使用的角色，或新增一个重复标识成员，界面立即展示服务端拒绝原因。

## 主要文件

- `server.js`：HTTP API、静态文件、Server-Sent Events 实时推送；
- `core.js`：成员、角色、范围、冲突、快照、失效数据和待处理操作的事务逻辑；
- `public/index.html`、`public/app.js`、`public/styles.css`：启动即见的可操作界面；
- `core.test.js`：离线回归测试。
