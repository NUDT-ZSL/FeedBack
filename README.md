# 运维日志链可信性核查工具

完全离线运行（仅 Python 3 标准库，无第三方依赖、无网络请求），
对按时间顺序追加的运维日志链做完整性核查、增量复核与人工裁决管理。

## 快速开始

```bash
python -m logchain.server 8765     # 启动后浏览器打开 http://127.0.0.1:8765
```

界面中点击「载入示例数据」即可看到一条 40 条的演示链，
其中包含 4 类典型问题：正文被篡改、校验值缺失、校验值格式异常、
前序引用指向不存在的顺序号。

## 日志格式

每行一条 JSON 记录（JSONL），按追加顺序排列：

```json
{"seq": 1012, "time": "2026-09-20T08:11:00", "source": "authd",
 "body": "user admin login success", "prev_seq": 1011,
 "checksum": "<64位十六进制>"}
```

校验值算法：`checksum = sha256("v1\n{seq}\n{time}\n{source}\n{body}\n{prev_checksum}")`，
首条记录的 `prev_checksum` 取 64 个 `0`。每条记录的校验值都基于前序记录的
校验值生成，因此任何一处改动都会使该点之后的链条失去可信基础。

## 功能与需求对应

1. **载入与查看**：载入 JSONL 日志链，表格展示完整链条（顺序号、时间、
   来源、正文、前序引用、校验值、状态、裁决）。
2. **完整性校验**：逐条重算校验值并比对，报告首个不一致记录的位置
   （`first_bad_seq`）及其影响范围（该记录到链尾的全部记录）。
3. **增量复核**：修改正文 / 顺序号 / 校验依据后，只重算受影响区间
   （修改点到链尾），之前的结论直接复用；服务端同时做一次全量校验
   对照，返回 `matches_full` 证明两种结论一致（界面与报告均展示
   重算/复用条数）。
4. **可疑标记**：校验值缺失、格式异常（非 64 位十六进制）、前序引用
   指向不存在的顺序号、顺序号重复、记录无法解析，均标记为「可疑」
   并给出具体原因，绝不跳过或当作通过。
5. **定位与差异**：点击任意记录（或「定位首个可疑」）查看原始内容、
   期望校验值与实际校验值的差异、异常原因，以及该记录对后续链条的
   影响说明。
6. **裁决管理**：对可疑记录保存裁决（确认篡改 / 接受现状 / 误报 /
   待调查）与备注，持久化在 `<日志文件>.adjudications.json`，与校验
   结论分离存储。校验依据再次变化时只重算受影响区间的结论，全部裁决
   原样保留；若裁决所依据的校验值已变化，界面会标注「依据已变化」。

## 记录状态

| 状态 | 含义 |
| --- | --- |
| ok | 校验值与依据一致，且不受前序问题影响 |
| mismatch | 校验值与依据不一致（内容或顺序可能被改动） |
| suspicious | 校验值缺失 / 格式异常 / 悬空引用 / 顺序号重复 / 无法解析 |
| affected | 本身校验通过，但链条在其之前已断裂，结论依赖断点处置 |

## 修复工作流

在详情面板中修改记录后，可选择「重算本条校验值」或「从本条起重算
全链校验值」。修正断点并提交后，系统只增量复核受影响区间，链条可
恢复为全部通过。

## 测试

```bash
python -m unittest discover -s tests -v   # 单元测试（10 项）
python scripts/e2e_check.py               # 端到端冒烟（启动真实服务）
```

## 目录结构

```
logchain/model.py    记录模型与校验值算法
logchain/chain.py    校验引擎：全量 / 增量校验、影响范围、记录修改
logchain/store.py    裁决持久化（与校验结论分离）
logchain/server.py   本地 HTTP API 与界面服务
static/              单页界面（原生 JS，无外部依赖）
sample_data.py       示例数据生成器
tests/test_chain.py  单元测试
scripts/e2e_check.py 端到端冒烟脚本
```
