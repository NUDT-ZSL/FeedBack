# 多渠道反馈分流系统

运营人员导入工单、社区、客服记录等渠道的用户反馈,系统自动归并重复诉求、
识别矛盾说法,并按影响面与紧急度给出可解释的分流建议。

## 运行

```
python server.py
```

浏览器打开 http://127.0.0.1:8787 (端口可用环境变量 PORT 修改)。
数据持久化在 `data.json`,无需第三方依赖(仅 Python 3 标准库)。

## 功能与需求对应

1. **多渠道导入**:界面「导入反馈」支持行式 `来源|功能点|报告时间|文本` 或 JSON 数组;
   导入后立即进入待处理视图。「导入示例数据」可一键载入演示数据。
2. **诉求归并**:同功能点下按文本相似度(单字/二字 Jaccard 各半,阈值 0.08)自动归并,
   各来源原始表述全部保留,归并依据(相似度、阈值、时间)在诉求详情中可查。
3. **矛盾识别**:内置规则检测功能去留、默认行为、性能感受、易用性、稳定性五类矛盾;
   双方说法同时保留并标记「待裁定」,系统不静默选边。
4. **裁定与优先级**:运营选择处理去向(立即修复/排期优化/转需求评审/暂不处理/需要更多信息),
   系统按 `影响面×2 + 紧急度×3` 重算最终优先级(P0-P3)并刷新整体分流排序,依据完整展示。
5. **判定失效与重确认**:已裁定诉求收到新反馈时转入「待重审」,旧去向冻结,
   必须重新确认去向后才恢复生效。
6. **界面操作**:待处理列表、分流结果表、诉求详情(原始表述/归并依据/矛盾/裁定记录)
   均在同一页面完成归并查看、矛盾裁定与去向调整;底部保留完整操作审计日志。

## 文件

- `analysis.py` 文本相似度、紧急度、矛盾检测、影响面与优先级计算(纯规则、可解释)
- `server.py` HTTP 接口与静态服务、JSON 持久化
- `static/` 单页前端(index.html / app.js / style.css)
