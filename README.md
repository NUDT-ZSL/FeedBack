# 曲水流觞

六只羽觞沿弯曲渠道漂流的 3D 演示（React + Three.js / R3F + zustand）。

- `npm run dev`：本地启动（默认 http://localhost:3000）
- `npm run build`：类型检查与生产构建
- `npm test`：离线运行推进/碰撞模拟验证（vitest，无需浏览器）

## 推进与碰撞模拟

羽觞的推进、停转与碰撞全部收敛在 `src/sim/cupSimulation.ts` 这份纯函数状态中：

- 每帧只调用一次 `stepSimulation(prev, env, delta)`，输出只依赖上一帧的确定状态，
  场景在 `useFrame(..., -1)` 中统一推进，各杯只读取推进后的同一结果渲染。
- 碰撞按杯对（`i < j`）每帧只检测一次；杯对进入接触后记入 `contacts`，
  间距拉开超过 `SEPARATION_DISTANCE` 才解除，同一对杯不会跨帧重复计数。
  碰撞响应对双方对称（等质量交换速度；一方停转时另一方反弹）。
- 停转采用统一滞回：水深低于 `STUCK_DEPTH`（0.12）卡住，
  高于 `RELEASE_DEPTH`（0.15）才恢复，阈值之间的开度抖动不改变卡住标记。
- `createInitialSimState()` 是唯一初始分布：六只杯按 `INITIAL_SPACING` 等间距排列，
  速度、卡住标记、接触记录与累计碰撞全部归零。重置与停止自动演示都会通过
  store 中的 `simResetToken` 让场景回到这个收敛点，并清零碰撞计数。
- 每帧新增的碰撞数通过 `addCollisions(n)` 一次性写入 store，
  界面计数累加值恒等于模拟状态中的 `totalCollisions`。

## 离线验证覆盖的情形

`src/sim/cupSimulation.test.ts` 覆盖：

1. 同帧多杯：三只贴近杯体同一帧产生两个杯对，只计两次；持续贴近不重复计数，分离后可再次触发。
2. 阈值附近开度抖动：在 0.12–0.15 滞回区间内反复抖动，卡住标记不抖动；越过恢复/卡住阈值才翻转。
3. 重置：任意推进后重新初始化，所有杯体回到同一初始分布。
4. 自动演示切换：重放相同的三角波开度序列，最终状态逐字段一致；store 的重置/停止都提供统一收敛点。
5. 计数一致：一帧一帧上报的碰撞事件数累加后等于模拟内的总碰撞数。

## 如何观察推进与计数一致

- 运行 `npm run dev`，左上角「碰撞次数」每次加 N，都对应同一帧场景中发生的 N 个杯对碰撞，
  杯体同时出现倾斜晃动，渠中央金色点光同步闪烁（约 300ms 衰减）。
- 把水闸开度拉到接近 0：杯体停住并侧倾；在临界附近快速来回拖动滑块，
  杯体不会反复卡住/启动，只有越过两个阈值时状态才翻转。
- 点击「重置」或「自动演示」后再「停止」：六只杯立即回到渠首等间距初始位置，
  碰撞次数回到 0，随后计数与场景中实际碰撞继续一一对应。
