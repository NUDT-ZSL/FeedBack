# AutoDemo 本地生产队列

这是一个零外部依赖的本地队列演示系统，用 Python 标准库提供多机排程、故障隔离、分段恢复和浏览器操作台。

## 启动

```powershell
python -m queueplanner --manifest examples/queue.json --port 8765
```

打开 `http://127.0.0.1:8765`。页面会每 0.9 秒刷新一次，可暂停虚拟时钟、单步推进，也可在页面中载入另一份本地 JSON 清单。

## 输入清单

清单包含三类对象：

- `machines`：机器和每日可用时段；省略 `availability` 表示全天可用。
- `materials`：素材的 `id`、名称、版本和本地路径。
- `tasks`：任务时长、显式依赖 `depends_on`、取用素材 `materials`、产出素材 `produces`、允许机器 `machines`。

当任务 A `produces` 某个素材、任务 B 在 `materials` 中取用该素材时，系统会自动加入 A → B 的依赖。同一份清单也可以继续用 `depends_on` 表达人工先后约束。

系统会拒绝以下输入：重复 id、不存在的素材/机器/任务引用、非正任务时长、非法可用时段，以及直接或间接循环依赖。

## 排程与恢复语义

排程器执行拓扑校验，按下游关键路径长度给任务排序，再结合每台机器的每日窗口和任务最早可开始时间确定机器与开始时间。带多机、窗口和先后约束的排程本身是 NP-hard，这里采用确定性的关键路径列表调度：先保证关键下游不被短任务挤后，再在当前可执行机器中选择最早完成的机器。它适合每天几百条任务的快速稳定重排；任务一旦开始不可被抢占。

失败处理只影响故障任务的传递下游：

1. 失败任务标记为“失败”。
2. 直接或间接依赖它、尚未完成的任务标记为“受阻”。
3. 与故障无关、已经完成或可执行的任务继续推进。
4. 失败任务重试后，其下游自动回到等待并恢复排程。

界面同时展示“实时完成顺序”和“基线逻辑顺序”。重试不会重做无关任务；为避免新旧结果混用，已完成任务的最终结果按依赖安全的基线逻辑顺序校验。若任务原本被允许在多台机器执行，暂停一台机器后会自动改派到其他当前空闲且处于可用窗内的机器；暂停不会杀掉正在运行的任务。

## 素材替换

选择素材并输入新版本后，先执行影响分析：

- 直接取用该素材的任务；
- 这些任务的全部传递下游；
- 每个受影响任务当前状态。

用户可以勾选重跑范围。选择一个已产出任务时，后端会自动把它的传递下游纳入重跑闭包，防止旧输出与新素材混用。也可以选择接受旧结果放行；任务行将保留“已接受旧结果”的提示。
