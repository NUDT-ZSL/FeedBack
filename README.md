# 离线笔记：断网编辑 / 重连同步 / 冲突解决

一个本地即可运行的离线优先笔记应用，完整演示"断网编辑 → 本地队列 →
重连顺序提交 → 冲突检测 → 并排差异 → 人工解决 → 断点续传"整条链路。
仅依赖 Python 3 标准库，无需安装任何第三方包。

## 启动

```
python server.py
```

然后浏览器打开 http://127.0.0.1:8765

运行自动化测试（需先启动服务端）：

```
python test_sync.py
```

## 演示流程

1. 正常新建/编辑笔记，改动会立即提交（队列中标记"已提交"）。
2. 点右上角"模拟网络"开关断网，继续新建、修改、删除笔记——
   所有改动进入右侧"待提交队列"，状态为"待提交"。
3. 重新打开开关，队列按产生顺序自动逐条提交，每条显示状态与结果。
4. 制造冲突：先断网修改某条笔记，再点"模拟服务端被他人修改"
   （相当于另一个客户端提交了新版本），然后恢复网络——
   提交时服务端返回 409，该改动标记为"冲突"，同笔记后续改动被"阻塞"。
5. 点击右侧冲突条目，弹出并排差异视图（本地 vs 服务端，行级高亮），
   并说明冲突原因（本地基于 vX 修改、服务端已到 vY、各自时间）。
6. 选择"保留本地"/"保留服务端"/"手动合并"，结果提交服务端，
   队列中相关改动标记为"已解决"。
7. 提交过程中再次断网：已完成的改动不会重复提交（服务端按 op_id
   幂等去重），未完成的保留在队列中，下次重连后续传。

## 架构

- `server.py`：服务端。SQLite 存储笔记（带 version 乐观锁）和
  已应用的 op_id（幂等）。接口：
  - `POST /api/op`：应用一条改动；基线版本不符返回 409 + 服务端快照
  - `POST /api/resolve`：提交冲突解决结果（保留本地/合并）
  - `GET /api/notes`、`GET /api/state`：查询
  - `POST /api/debug/server-edit`、`/api/debug/reset`：演示/测试辅助
- `static/app.js`：前端。笔记与队列持久化在 localStorage；
  队列顺序提交、失败回滚为待提交、冲突阻塞同笔记后续改动、
  LCS 行级 diff、三种冲突解决方式。
- `test_sync.py`：16 项端到端 API 测试。
