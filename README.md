# 队列留存比较工作台（纯本地 / 离线）

一个**零依赖、纯浏览器运行**的渠道获客队列留存分析工具。数据全部来自本地
（localStorage / JSON 导入），不连接任何外部服务。

核心解决的问题：各渠道队列起跑时间不同、可观察期数长短不齐，用"总留存"直接排名
会把**只是观察得更久**的队列误判成表现差。本工具只在两个队列**都有有效观测的
共同观察窗口**内逐期对齐比较，窗口外的观测被明确排除并逐条说明原因——
**绝不当作 0，也不按缺失插补**。

## 启动

方式一（推荐，双击即可）：直接用浏览器打开 `index.html`。

方式二（本地静态服务）：

```bash
npm start          # 或 node server.js
# 打开 http://localhost:8123
```

首次启动自动载入内置演示数据；之后的一切改动保存在浏览器 localStorage。
顶栏可「导出 JSON / 导入 JSON / 恢复演示数据」。

## 测试

## 需求与实现对照

| # | 需求 | 实现位置 |
|---|------|----------|
| 1 | 队列维护（起始时刻/分层/规模/逐期活跃）、幂等、超规模与时刻倒退拒绝并指出位置 | `js/retention-core.js`：`addCohort` / `addObservation`（错误返回含 `location`、队列名、期、来源）；表单红框 + 位置提示 |
| 2 | 任意两队列只在共同窗口比较；窗口外观测排除并说明，不做零/缺失填补 | `compareCohorts`：`window` + `exclusions`（`BEFORE/AFTER_WINDOW`、`GAP_IN_WINDOW`）；图上窗口外画灰色幽灵点，下方逐条列原因 |
| 3 | 逐期留存率/差额/方向，检出窗口内反转并列具体期，重复比较完全一致 | 比较结果含 `rows[]` 与 `reversals[]`；反转横幅 + 表格「⇄ 反转点」；纯函数结果 + 签名缓存，同输入同一对象 |
| 4 | 分层队列数低于下限标为不可比，说明还缺多少，不与充足分层并列下结论 | `strataSummary`：`comparable/missing/note`；分层卡片红色不可比标记；跨分层比较另挂警示，不输出分层优劣 |
| 5 | 多来源矛盾值双方保留 + 可读冲突记录（队列/时刻/来源/数值），不静默择一 | `addObservation` 生成 `conflicts`（pending），原始观测全部保留；冲突面板可按候选值或自定义值裁决，记录永久留存 |
| 6 | 增量更新：未受影响比较不变，受影响部分与全量重算一致 | 不可变更新 + 按队列内容签名的结果缓存；`fullRecompute` 在全新状态重放后比对；测试与界面自检对全部队列对做了逐对校验 |
| 7 | 启动即出现可操作界面，新增观测/更换对象后即时反映结果与拒绝原因 | 单页应用：留存矩阵热力图、共同窗口曲线、分层卡、逐期表、冲突面板；任一提交后立即持久化并重渲染 |

## 关键语义约定

- **观察期**：相对期（第 0 期 = 各队列自己的起跑期）。比较按相对期对齐，
  与日历起跑日无关；起跑时刻仅用于展示。
- **留存率** = 该期有效活跃数 / 队列规模。规模可修正（留痕于 `scaleHistory`），
  但新规模小于任何已观测活跃数时拒绝并逐期指出。
- **"未观测"与"0%"严格区分**：矩阵中未观测期为虚线空格，不参与任何统计。
- **未裁决冲突期不进入共同窗口**：即使双方该期都有数据，也以
  `UNRESOLVED_CONFLICT` 排除，直到人工裁决。
- **时刻倒退**：只拒绝"给从未上报过的历史期补数据"；历史期的消息重投按幂等
  忽略，历史期迟到的另一来源矛盾值按冲突双方保留。

## 离线与隐私

- 无任何第三方库、无 CDN、无字体/图片外链、无网络请求。
- 数据仅存于本机浏览器 localStorage；「导出 JSON」是唯一的外带方式。
