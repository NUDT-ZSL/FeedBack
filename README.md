# 媒体生产队列工作台

纯本地、离线运行的媒体加工任务编排工具：在有限的处理通道上安排批量素材加工任务，
组织每项任务的产出与失败情况。不依赖任何在线服务，直接用浏览器打开 `index.html` 即可使用。

## 运行

- 双击打开 `index.html`（或任意静态方式托管本目录），无需构建、无需联网。
- 首次启动自动载入一个 10 任务 / 6 素材 / 3 通道的示例批次，立即可操作。
- 数据保存在浏览器 localStorage，刷新后状态保留；点「清空」可重置。

## 功能与需求对应

1. **任务录入**：左侧表单登记素材标识、录入任务（加工类型 / 预计耗时 / 优先级 1-9），
   并勾选任意前置依赖；「载入示例批次」可一键生成演示数据。
2. **确定性调度**：`scheduler.js` 的列表调度算法以「优先级降序 → 耗时升序 → ID 字典序」
   为稳定排序键，通道冲突时取编号最小者；同一批输入无论顺序如何、重复多少次，
   输出完全一致的执行顺序与通道分配（有自动化测试保证）。
3. **失败传播**：任务行点「失败」后，沿依赖边求传递闭包，所有下游任务立即标记为
   「待重试」并释放其槽位，右侧面板列出失败任务与受影响下游。
4. **增量重算**：重试或修改优先级后，仅未完成任务参与重算（已完成任务的槽位作为
   固定保留），调度核心是同输入必同输出的纯函数，因此结果与整批从头调度一致；
   点「一致性校验」可随时核对。
5. **问题阻断**：录入数据若存在循环依赖、引用未登记素材、依赖未知任务或 ID 重复，
   顶部红色横幅逐条列明问题任务并阻止该批调度，绝不静默跳过。
   「载入异常示例」可演示该行为。
6. **编排界面**：启动即见任务队列（状态徽章）、通道占用甘特图、失败与重试面板、
   调度日志；点「重试」可立即看到状态与甘特图变化。

演示参数：`index.html?scenario=fail` 模拟 T03 失败；`?scenario=bad` 演示异常批次阻断。

## 文件结构

- `scheduler.js` — 调度核心（纯函数，无 DOM 依赖）：校验、确定性调度、下游闭包
- `app.js` — 状态管理与界面渲染（localStorage 持久化）
- `index.html` / `styles.css` — 页面结构与样式
- `tests/` — Node 自动化测试（核心逻辑 + 界面流程冒烟）

## 测试

```
npm test
```

或分别执行：`node tests/scheduler.test.js`、`node tests/app.smoke.js`、`node tests/app.flow.js`。
