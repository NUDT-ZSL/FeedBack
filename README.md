# 多渠道反馈分流台

运营人员导入工单、社区、客服记录等渠道的原始反馈后，系统自动归并重复诉求、
标记相互矛盾的说法，并按影响面 × 紧急度给出可解释的分流建议；运营在界面上
完成归并确认、矛盾裁定与去向调整。

## 运行

```bash
python app.py          # 打开 http://127.0.0.1:5000
python -m unittest discover -s tests   # 运行测试
```

数据持久化在 `data.json`（每次操作自动保存），界面上的「清空数据」可重置。

## 需求对应实现

1. **多渠道导入**：`POST /api/import` 接收 `{source, text, feature, reported_at}`
   列表，导入即进入待处理视图；界面支持逐行 JSON 导入和一键载入示例数据。
2. **归并**：字符二元组 Jaccard 相似度 + 同功能点加权，超过阈值自动并入同一
   诉求；每条被归并的反馈保留来源原文，归并依据（相似度、共同特征、匹配功能点）
   展示在反馈下方，需运营确认或拒绝（拒绝则拆分为新诉求）。
3. **矛盾检测**：内置反义词组（保留/去掉、太快/太慢、喜欢/讨厌等），同一诉求下
   命中对立说法即生成「待裁定」矛盾卡片，双方表述始终同时保留，裁定时只记录
   结论说明，绝不丢弃任一方。
4. **裁定与重算**：运营选择去向（立即修复/排期优化/暂不处理/需要更多信息）与
   优先级（P0–P3）后，最终优先级立即以裁定值为准，整体分流排序实时重算；
   未裁定时使用系统建议值（影响面 = 来源数×2+反馈数，紧急度 = 严重词+时效）。
5. **依据变化保护**：已裁定诉求并入新反馈时，旧裁定自动移入历史并标记失效，
   状态变为「需重新确认」，界面红色警示；重新确认前最终优先级回落为系统建议值，
   不沿用旧结论。
6. **界面**：诉求卡片展示合并情况、矛盾标记、优先级排序与完整裁定记录
   （右侧审计流），归并确认、矛盾裁定、去向调整、诉求手动合并均可在界面完成。

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/board` | 分流看板（含计算字段与审计日志） |
| POST | `/api/import` | 批量导入反馈 |
| POST | `/api/demands/<id>/merge-confirm` | 确认/拒绝归并 |
| POST | `/api/demands/<id>/contradictions/<cid>/resolve` | 裁定矛盾 |
| POST | `/api/demands/<id>/adjudicate` | 裁定去向与优先级 |
| POST | `/api/demands/merge` | 手动合并两个诉求 |
| POST | `/api/sample` / `/api/reset` | 示例数据 / 清空 |
