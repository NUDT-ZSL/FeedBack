# AutoDemo · 离线分块接收与后台转换

完全本地离线运行，仅依赖 Python 3.8+ 标准库，无外部存储、无在线服务。

## 运行

```
python server.py
```

浏览器打开 http://127.0.0.1:8000 （可用环境变量 `PORT` 改端口）。

## 功能与需求对应

1. **分段接收与实时进度**：添加文件时设定分段大小，浏览器在本地用
   `Blob.slice` 切片并逐段上传（附 SHA-256 校验和）。界面以颜色网格实时
   显示每个分段状态与接收/转换两条进度条。
2. **失败分段独立重试**：接收失败（校验和不匹配、故障注入）只把该分段
   标记为失败并记录可读原因，已成功分段原样保留；点击红色分段或
   “上传/继续接收”只重传失败分段，绝不从头重传。
3. **后台转换断点续传**：全部分段就绪后自动启动后台转换线程，逐段转换
   并原子落盘（`.tmp` + `os.replace`）。“中断转换”后状态变为“转换已中断”，
   “继续转换”从第一个未转换的分段继续，已转换部分不重做。
4. **冲突保留与裁决**：某分段新接收内容的校验和与先前记录不一致时，
   新旧内容双方都保留（新内容存入 `conflicts/``），并计算首个/末个差异字节
   位置与不同字节数；界面弹出裁决窗口，由使用者选择“保留原有”或
   “采用新内容”后才继续后续处理。
5. **局部更新与最终一致**：裁决“采用新内容”只作废该分段的转换结果与
   最终产物，其余分段的转换结果保持原样，后台仅重转受影响分段。
   “一致性校验”按钮从源分段整体重推最终校验和，与增量结果对比，
   保证二者一致。
6. **状态区分与即时反馈**：等待/接收中/已接收/失败/冲突/转换中各有
   独立颜色与图例，操作后界面立即刷新，失败分段悬停可见可读原因。

## 演示辅助

- **故障注入率**：按比例随机让分段接收失败。
- **下次接收必失败**：精确制造一次失败，用于演示单段重试。
- **转换延时**：放慢转换过程，便于演示中断/续转。
- **模拟冲突重传**：篡改一个已接收分段的 1 字节后重传，触发冲突裁决流程。

## 测试

```

```

端到端覆盖：失败重试、有序接收与进度、转换中断/续转、冲突检测与差异
定位、裁决后局部重转、增量结果与整体重推一致、幂等重传。

## 数据布局

```
data/app.db                      SQLite（任务、分段、设置）
data/files/<id>/chunks/          已确认分段
data/files/<id>/converted/       分段转换结果
data/files/<id>/conflicts/       冲突的新内容（待裁决）
data/files/<id>/output.bin       最终转换产物
```
