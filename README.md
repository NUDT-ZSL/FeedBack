# 协作编辑协调工具

本地可启动的多人编辑合并确认工具: 载入带章节结构的文档与多位协作者的
编辑记录, 自动识别重叠/依赖关系并给出可确认的合并结果, 支持逐条接受、
拒绝或手动调整, 并实时生成最终文档与未解决冲突清单。

## 启动

仅需 Python 3.8+, 无第三方依赖:

```
python server.py --port 8000
```

浏览器打开 http://127.0.0.1:8000/

## 功能与需求对应

1. **载入文档与编辑记录**: `sample_data/document.json` 为章节层级文档,
   `sample_data/edits.json` 为编辑记录 (author / op / target / content /
   depends_on / note)。替换 `sample_data/` 下两个文件即可载入自己的数据。
2. **重叠与依赖识别**: 同段落多条替换做词级 diff, 变更区间不重叠时自动
   合并为单一结果; 重叠、删除与修改并存等情况标记为冲突而非简单覆盖。
3. **逐条确认**: 中间栏展示每处改动的来源、冲突情况与合并结果, 可接受、
   拒绝, 或在"手动调整"中直接编辑该段最终文本。
4. **联动更新**: 系统只持久化用户决策, 合并结果/失效状态/最终文档全部由
   决策派生, 任何接受或拒绝都会触发整体重算, 不会残留矛盾内容。
5. **失效标记**: 依赖的编辑被拒绝、或目标段落被已接受的删除编辑移除时,
   相关记录标记为"已失效"并显示具体原因。
6. **状态总览**: 左栏为章节树 (含待定/冲突徽标) 与未解决清单, 右栏实时
   显示最终文档。

## 编辑记录格式

```json
{
  "id": "e1",
  "author": "小林",
  "op": "replace | delete | insert_after",
  "target": "p4",
  "content": "新段落文本",
  "depends_on": ["e0"],
  "note": "备注"
}
```

## 测试

```
python -m unittest discover -s tests -v
```

## 文件结构

- `merge_engine.py` — 合并引擎: 词级 diff、冲突检测、失效推导、最终文档生成
- `server.py` — 标准库 HTTP 服务与 JSON API
- `static/` — 单页前端 (章节树 / 改动确认 / 最终文档三栏)
- `sample_data/` — 示例文档与编辑记录
- `tests/` — 引擎单元测试
