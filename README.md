# 车间一日调度推演

这是一个纯本地运行的交互式排产应用，用来推演多台设备在一天内的启停、档位切换、能耗账单和任务交付。

## 启动

方式一：双击 `start.bat`。

方式二：在当前目录运行：

```powershell
python app.py --port 8766
```

然后打开 <http://127.0.0.1:8766/>。只需要 Python 3.10+，不安装任何第三方依赖。

## 界面操作

- 打开后自动加载 `sample/` 下的设备、任务、过渡和分时电价数据。
- 分别导入设备、任务、过渡 CSV 后，页面立即重新排产；可只替换其中一个文件。
- 点击时间轴上的生产块，可以修改档位、启动/停止时间，或删除手动锁定块。
- 在“新增手动安排”中锁定任务、设备、档位和启停时段；调度器会补齐剩余任务。
- 若当前调整导致任务迟交，顶部会列出冲突任务、相关设备与原因，并给出一份清空手动调整后的可行替代方案。
- 可以导出当前方案为 `schedule_plan.csv`。

## CSV 格式

### 设备 `devices.csv`

| 列 | 含义 |
| --- | --- |
| `id` / `name` | 设备编号和名称 |
| `modes` | 档位，格式 `LOW:功率kW,产出/小时;HIGH:功率kW,产出/小时` |
| `shift_start` / `shift_end` | 当天允许启停窗口，支持 `HH:MM` |
| `max_run_slots` | 当日最多生产的 5 分钟时间槽数量 |
| `maintenance_window` | 维护窗口，`HH:MM-HH:MM`；多个窗口用 `;` 分隔 |

### 任务 `tasks.csv`

| 列 | 含义 |
| --- | --- |
| `id` / `name` | 任务编号和名称 |
| `quantity` | 需要完成的产出数量 |
| `release` / `deadline` | 最早开始和最终截止时间 |
| `depends_on` | 前置任务，多个任务用 `,` 分隔 |
| `allowed_devices` | 可承接设备，多个设备用 `;` 分隔；为空则所有设备可承接 |

### 过渡 `transitions.csv`

| 列 | 含义 |
| --- | --- |
| `device_id` | 设备编号 |
| `from` / `to` | `OFF` 与档位，或两个不同档位 |
| `duration_slots` | 过渡占用的 5 分钟时间槽数量 |
| `rate` | 过渡功率 kW；过渡期间不产出但计费 |

### 分时电价 `tariff.json`

`tariff` 为 24 个小时电价，单位为元/kWh。也可以由 API 传一个统一电价或 288 个时间槽电价。

## 调度模型

- 一天分为 288 个 5 分钟时间槽。
- 自动排产会按任务依赖顺序填满产量，任务可以拆分给多台可用设备。
- 维护窗口和启停窗口之外不安排生产或过渡；维护窗口中的设备会迫使任务转移。
- 每次生产前检查前序状态并插入开机或跨档位过渡，过渡不产出但计入能耗。
- 档位选择会比较各设备的完工时间和单位能耗，在满足有效截止时间的前提下自动组合。
- 下游任务会反向收紧前置任务的截止时间，避免“前工序按时、但后工序无时间完成”。
- 当前方案不可行时，系统保留设备维护和产能上限，清空手动安排重新生成替代方案；若替代方案仍冲突，说明设备总产能或维护约束本身不足。

## 验证

运行自动化测试：

```powershell
python -m unittest discover -s tests -v
```

测试覆盖样例可交付、维护窗口下转移任务、手动错误调整以及替代方案生成。
