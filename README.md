# 现场工单 · 离线编辑与同步对账

零依赖全栈演示（Node 18+，无需 npm install）。现场人员可在弱网/断网下继续编辑工单，
恢复连接后按序提交本地操作，与服务端做字段级对账，冲突时并列展示双方值并支持人工裁决。

## 启动

```bash
node server.js        # 或 npm start
# 打开 http://localhost:3000 ，直接进入工单编辑界面
```

## 验证

```bash
node server.js        # 终端 1
node test/e2e.js      # 终端 2，14 项断言覆盖合并/冲突/裁决/幂等
```

## 核心机制

- 离线编辑：每次修改标题/正文/负责人都会生成一条操作记录
  `{seq, workorderId, field, oldValue, newValue, time}`，存入 localStorage，
  界面即时更新并标记「待同步」，刷新页面不丢失。
- 按序提交：重连后客户端把操作日志按 seq 顺序发给 `POST /api/sync`。
- 最终意图合并：服务端把同一 `(工单, 字段)` 的多条操作折叠为
  「首条 oldValue 作基线 + 末条 newValue 作意图」，中间过程仍保留在客户端日志中可回看。
- 三方判定：服务端当前值 == 基线 → 安全应用；== 意图 → 幂等跳过；
  否则 → 冲突，返回双方值，绝不静默择一。
- 冲突裁决：界面并列展示本地意图与服务端当前值，可选「保留本地 / 保留服务端 /
  手工输入」，提交到 `POST /api/resolve`；服务端只重算被裁决的工单与字段，
  其余已同步结果原样保留，并带 `expectedServerValue` 防止裁决期间再次过期。

## 演示流程

1. 点「模拟断网」，连续修改某工单的标题两次、负责人一次 —— 字段出现「待同步」标记，
   右侧操作记录中可看到中间值被标记为「已被后续修改覆盖」。
2. 断网期间点「模拟服务端变更」（需先恢复在线点一次再断网，或在在线时先点），
   模拟另一终端改了同一工单。
3. 点「恢复连接」，自动按序同步：安全字段直接应用，冲突字段进入裁决面板。
4. 在裁决面板选择一方或输入手工合并值，点「提交裁决」，仅受影响字段被重算。

「重置演示数据」可恢复初始工单并清空本地队列。
