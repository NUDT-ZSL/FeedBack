# 成片生产队列：依赖约束排程 + 失败局部恢复

纯 Python 标准库实现（Python 3.10+），零第三方依赖。模拟时钟驱动，
1 个真实秒推进 5 个模拟秒，方便在界面里观察整条队列。

## 运行

```
python server.py              # 启动本地控制台，默认 http://127.0.0.1:8000
python server.py --fresh      # 忽略旧检查点，从头排一轮
python test_core.py           # 运行全部核心测试
```

## 清单格式（manifest.json）

- `materials`：素材（id、名称）。任务可用 `produces` 声明产出的素材，
  其他任务通过 `uses` 取用时自动形成隐式先后依赖。
- `tasks`：任务时长（模拟秒）、`uses` 取用素材、`depends_on` 显式先后依赖、
  `produces` 产出素材、`machine_type` 机型要求。
- `machines`：每台机器的 `type` 与可用时段 `windows: [[开始, 结束], ...]`，
  任务只有在当前时段内能完整执行时才会被派发到该机器。

读入时做三类校验：依赖不存在的任务、任务依赖自身、循环依赖（Kahn 拓扑排序
检测），任一不满足直接拒绝加载并指出涉及任务。

## 排程策略

事件驱动的确定性列表调度：每个 tick，每台空闲、未暂停且处于可用时段的机器，
在"前置全部完成"的就绪任务中按 **关键路径长度降序、任务 id 升序** 取优先级
最高者派发。关键路径优先保证链长的任务早开工，使整批尽早完成；排序键完全
确定，同一场景重复运行结果一致。

## 失败与恢复（只重做受影响的一段）

- 某任务失败后：任务置为"失败"，只有其**传递下游**变为"受阻"；无关任务
  继续在各自机器上推进，整批不停摆。
- 操作员点"重试"后，任务重新排队；其下游在失败前置恢复后自动解除受阻。
- 调度优先级不随故障历史变化，恢复后按同一确定性策略派发，因此受影响链路
  的完工顺序与无故障运行一致（见 `test_core.py`）。失败本身带来的延迟和
  操作员主动暂停机器造成的改派会改变绝对时刻，但不改变依赖决定的先后关系。
- 状态每个 tick 原子写入 `state.json`，进程/机器重启后自动从断点继续，
  不必从头再来。

## 界面操作

- 机器卡片：暂停（在跑任务撤下改派其他机器）/ 恢复；非可用时段置灰。
- 任务行：对进行中的任务"模拟失败"、对失败任务"重试"；等待/进行/受阻/
  失败/完成/待裁决六种状态带颜色徽标、进度条、所在机器与预计完成时刻。
- 素材卡片：点"替换素材"后，系统圈定所有已执行/执行中且取用该素材的任务，
  列出影响范围并标记"待裁决"；操作员选择"全部重跑"（受影响任务及其下游
  完成节点一并重置）或"保留旧产出"（忽略替换）。
- 页面 500ms 轮询一次 `/api/state`，顶部显示模拟时钟、整批完成标记，
  底部为实时事件日志与最终完工顺序。

## 文件

- `scheduler_core.py`：模型、清单加载、依赖图、循环检测、优先级
- `scheduler_engine.py`：排程引擎（失败/重试、暂停、素材替换、检查点）
- `server.py`：HTTP API 与静态页面服务
- `static/index.html`：本地控制台界面
- `manifest.json`：12 任务 / 3 机器 / 5 素材的示例批次
- `test_core.py`：7 组核心场景测试
