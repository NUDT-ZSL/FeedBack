# 离线现场笔记

这是一个零第三方依赖的本地全栈示例，用来完整跑通“断网编辑 → 重连顺序提交 → 冲突解释 → 人工解决 → 中断重试”的链路。

## 启动

```powershell
npm start
```

然后打开：

```text
http://localhost:3000
```

运行自动化验证：

```powershell
npm test
```

## 离线与重连

- 右上角“切到离线”会进入应用内离线模式，此时仍可新建、修改、删除笔记。
- 所有操作立即保存到浏览器 LocalStorage，并进入“待提交队列”。
- 重连后按 `#序号` 顺序提交；每项显示等待、提交中、失败、冲突、已提交、已解决等状态。
- 已提交操作携带稳定的 `opId`。提交过程中断网时，未确认操作保留原 `opId`；服务端按 `opId` 幂等处理，重试不会重复生效。
- Service Worker 只缓存应用外壳（HTML/CSS/JS），不缓存 API 和笔记数据。

## 复现冲突

1. 在线时新建一条笔记，等待提交成功。
2. 切换到离线，编辑这条笔记并保存，队列中会出现修改操作。
3. 勾选“每次提交延迟 2.5 秒”。
4. 切回在线，在该队列项仍处于“提交中”时点击“模拟服务端新版本”。
5. 本地提交收到 409 后停止，界面并排展示本地版本、服务端版本以及相对共同旧版本的行级差异。

也可以先离线编辑，再在服务端通过其他客户端修改同一笔记后重连。

## 冲突处理

冲突不会自动覆盖任何一方。可以选择：

- **保留本地并提交**：把本地最终内容或删除结果作为新版本提交。
- **保留服务端**：接受服务端当前版本，同时把相关本地队列项标记为已解决。
- **手动合并**：编辑标题、正文，或显式选择合并结果为删除，再提交新版本。

服务端采用乐观锁：普通修改/删除必须带基础版本；冲突解决也必须带冲突时看到的服务端版本。如果解决期间服务端再次变化，会再次返回冲突，界面要求基于最新版本重新确认。

## 数据位置

- 服务端数据默认保存在 `data/notes.json`。
- 浏览器本地队列保存在当前浏览器的 LocalStorage。
- 可用 `OFFLINE_NOTES_DATA` 指定测试或演示用数据文件。

## 主要文件

- `server.js`：HTTP 服务、静态文件、笔记 API、版本检查、幂等处理和 JSON 持久化。
- `public/app.js`：离线状态、本地队列、顺序同步、中断重试、冲突面板和交互。
- `public/sync-core.js`：队列投影、版本重放、冲突构造和行级差异的纯函数核心。
- `public/sw.js`：应用外壳离线缓存。
- `test/`：同步核心与服务端 API 的自动化测试。
