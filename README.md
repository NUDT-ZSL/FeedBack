# 渠道队列留存比较工作台

一套**完全离线**的本地浏览器分析工具，解决“各渠道队列观察期长短不齐，拿总留存直接排名会把只是看得久的队列误判成表现差”的问题。不接任何外部服务，数据只存在浏览器 localStorage。

## 启动

直接用浏览器打开 `index.html` 即可（无需服务器、无需构建、无网络请求）。
首次启动自动载入一组演示数据，覆盖：观察期长短不一、方向反转、来源冲突、分层队列数不足等典型场景。

## 功能与需求对照

| # | 需求 | 实现 |
|---|------|------|
| 1 | 队列维护：起始时刻、分层、规模、逐期活跃 | 「数据录入」面板新增队列/上报观测/修正规模 |
| 1 | 重复上报幂等 | 同队列+同期+同来源+同数值 → 幂等忽略，不改变任何版本号 |
| 1 | 活跃超规模 / 时刻倒退拒绝并指出位置 | 拒绝日志记录队列、期次、数值、来源；同一来源上报时刻必须单调不减 |
| 2 | 只在共同观察窗口内比较 | 两队列观察期取交集；窗口外观测逐条列出排除原因（超出对方范围/早于对方首期/缺口），绝不以零或缺失填补 |
| 3 | 差异可解释 | 逐期给出双方留存率与差额(pp)；方向用交叉相乘精确判定，反转列出具体观察期；纯函数计算，重复比较结果完全一致 |
| 4 | 分层队列数低于下限 → 不可比 | 顶栏可设下限；不足的分层标「不可比」并显示还差几个；不与充足分层并列得出优劣结论 |
| 5 | 多来源矛盾数值 | 双方数值都保留，冲突记录列出队列、观察期、双方来源与各自数值；冲突期在解决前不纳入任何比较，绝不静默择一 |
| 6 | 增量更新一致性 | 比较结果按 (队列A修订号, 队列B修订号) 缓存：无关变更 → 返回同一结果对象（界面显示缓存徽标）；受影响比较整体重算，因计算是纯函数，必然与从头全量重算一致（有序列化重放测试保证） |
| 7 | 启动即可操作 | 首屏直接展示留存矩阵、可比窗口、分层差异、不可比标记；任何录入/切换立即重渲染并显示接受/幂等/拒绝/冲突反馈 |

## 文件结构

- `index.html` / `style.css` / `app.js` — 界面层（只是状态的投影，任何变更后整体重渲染）
- `engine.js` — 核心引擎（纯逻辑，无 DOM 依赖，浏览器/Node 通用）
- `test.js` — 引擎测试：`node test.js`（19 个用例，按 7 条需求分组）
- `smoke.js` — 界面链路冒烟测试：`node smoke.js`（最小 DOM 桩下验证启动渲染、上报联动、拒绝反馈）

## 界面操作说明

- **留存矩阵**：行=队列（含分层/起始/规模），列=观察期，单元格为留存率（热度着色）；`⚠ 冲突` 悬停可见双方来源数值，`—` 为无观测。
- **队列两两比较**：选择 A/B 后显示共同窗口、逐期留存率与差额、方向反转列表、窗口外排除明细；结果未重算时显示「来自缓存」徽标。
- **分层比较**：摘要表给出每层队列数与可比状态；仅可比层可两两对比，层内队列逐期加总后比较。
- **数据录入**：上报时刻留空则自动递增；手工填写可用于演示「时刻倒退」拒绝。重置按钮恢复演示数据，清空按钮从零开始。
