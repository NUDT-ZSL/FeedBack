# 用户反馈聚类与需求线索系统

把零散的用户反馈自动聚成问题簇，支持研究员人工修订，并基于最终结果生成需求线索。

## 运行

```bash
pip install -r requirements.txt
python app.py
# 打开 http://127.0.0.1:5057
```

可导入 `sample_feedbacks.txt` 体验完整流程。
首次启动会自动下载中文句向量模型 BAAI/bge-small-zh-v1.5（约 100MB）；
下载失败或离线时自动降级为 TF-IDF 字符 n-gram 相似度，功能不变、精度略降。

## 测试

```bash
python -m pytest tests/ -q
```

## 核心设计

- **唯一真源 = 反馈列表 + 决策日志**。自动聚类与所有人工修订
  （移动 / 合并 / 拆分 / 冲突裁决）都会翻译成 must-link / cannot-link
  约束写入决策日志，然后调用 `clustering.recompute()` **从头全量重算**。
  因此界面展示的结果与全量重算结果在构造上必然一致（需求 4），
  不会残留旧归属或遗漏反馈。
- **聚类算法**：中文句向量（bge-small-zh）余弦相似度 + 约束凝聚聚类
  （average linkage，遵守 cannot-link 约束，must-link 组作为初始单元）。
  阈值自适应 = pairwise 相似度均值 + 0.7×标准差，夹在 [0.50, 0.80]，
  适配不同数据集的基线相似度。
- **冲突检测**：重算后扫描相似度 ≥ 冲突阈值（均值 + 1.5×标准差，
  高于聚类阈值）却分属不同簇、且尚无裁决记录的反馈对，提示研究员
  裁决；裁决结果写入决策日志并在后续重算中生效（需求 5）。
- **意图优先**：移动 / 合并操作会撤回与之矛盾的既有「分开」裁决，
  保证最新人工意图一定生效。
- **需求线索**：每个最终簇生成一条线索（代表句 = 簇内 medoid，
  附关键词与全部来源反馈），按簇规模降序排列（需求 6）。
- 状态持久化在 `data/state.json`，重启服务不丢失。
- 簇 id（C1、C2…）按簇内最小反馈 id 确定性生成，重算后可能重排；
  这是「结果 == 全量重算」设计的一部分，不代表数据丢失。

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 全量状态（反馈/簇/冲突/线索/决策日志） |
| POST | `/api/import` | 粘贴导入，`{"text": "每行一条"}` |
| POST | `/api/import_file` | 文件导入（multipart，.txt/.csv） |
| POST | `/api/move` | 移动反馈到目标簇或新簇 |
| POST | `/api/merge` | 合并两个簇 |
| POST | `/api/split` | 把簇内勾选的反馈拆为新簇 |
| POST | `/api/conflict` | 冲突裁决（merge / separate） |
| GET | `/api/leads` | 需求线索列表（按规模降序） |
| POST | `/api/reset` | 清空全部数据 |
