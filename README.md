# 离线设备采样链路推演台

这是一个零第三方运行依赖的本地交互应用，用来推演持续上报设备的采样交付、切批、断连续采、重复冲突和人工修正。

## 启动

Windows：

```bat
start-windows.bat
```

或在当前目录运行：

```powershell
python -m http.server 8765
```

然后打开：

```text
http://127.0.0.1:8765/index.html
```

页面和引擎均为本地静态文件，不需要安装 npm 包，也不会访问网络。

## 判定模型

- 每个设备独立维护序号槽位；重复、乱序和迟到记录都会保留。
- 数量批次按采集端物理交付段切分；策略调整或连接变化会关闭当前批次。
- 时间批次按采样时刻落窗；只有在配置或推导出的采样节拍可靠时，才把缺失序号放入具体窗口，否则列为无法归属。
- “完整”要求批次已闭合，且范围内每个序号都有采信记录。
- “部分缺失”表示批次已断连/阈值切换/窗口结束，但存在缺口，或当前批次仍开放。
- “不可信”表示存在未裁决的同序号不一致记录。系统不会静默选择其中一个值。
- 冲突可采信首个、采信最新或输入人工值；裁决和修正都是可重放事件，会立即更新相关批次和续采锚点。
- 每次事件后执行同源全量重放，并只发布前后快照中发生变化的批次，所以增量推送结果与从头全量推演一致。

## 续采建议

续采序号来自“无未裁决冲突的连续交付锚点 + 1”。历史空洞和未裁决冲突会单独列出，避免设备只补尾部而漏掉中间缺口。

## 内置演示

启动页面自动载入两台设备：

- `PUMP-A`：数量阈值、重复值冲突、断连重连、阈值从 4 调整为 3。
- `TEMP-B`：一分钟时间窗、中间缺失、断连重连、坏序号记录。

可以直接在右侧完成裁决、追加连接/阈值事件、修正批次证据中的记录值或采样时刻。

## 验证

```powershell
npm test
```

测试覆盖冲突保留与裁决、断连续采、阈值调整、时间窗修正、无法归属记录和全量重放一致性。
