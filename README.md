# 离线交接推演

这是一个零第三方依赖、可完全本地运行的交接上下文推演应用。它在责任从一个人转移到另一个人时，沿前置依赖判断每个事项的可完成性、自身上下文完整度和含上游链路的完整度，并明确标出缺失依赖、依赖成环、时效过期、上下文缺失和来源冲突。

## 启动

方式一：直接双击打开 `index.html`。

方式二：启动本机静态服务：

```powershell
npm start
```

然后访问 `http://127.0.0.1:8080`。整个应用不访问网络，也不安装运行时依赖。

## 界面能力

- 首屏直接显示交接事项列表、状态、自身完整度和含依赖完整度。
- 同一事项同一上下文键出现不同值时，保留全部来源并形成冲突。
- 冲突未裁决前，相关事项为“等待裁决”，推导不会把任一方当作事实。
- 可选择任一来源，也可输入手动裁决值和裁决依据。
- 可修改上下文内容、来源、失效时间，或停用上下文（模拟信息随交接丢失）。
- 修改或裁决后只重推该事项、同环事项及所有下游事项；界面会显示本次重推链路和复用事项。
- 缺失依赖和依赖成环均标记为“不可信”，并在依据中给出缺失 ID 或环成员。

## 数据格式

导入 JSON 可直接使用如下顶层结构：

```json
{
  "now": "2026-09-22T09:00:00+08:00",
  "handoffs": [
    {
      "id": "H1",
      "title": "事项标题",
      "role": "交出角色 → 接手角色",
      "dependencies": [],
      "requiredContextKeys": ["runbook"],
      "timeCritical": "时效标记",
      "sourceNote": "来源说明"
    }
  ],
  "contexts": [
    {
      "id": "C1",
      "handoffId": "H1",
      "key": "runbook",
      "value": "上下文内容",
      "source": "来源系统或人员",
      "validUntil": "2026-09-30T18:00:00+08:00",
      "note": "补充说明"
    }
  ]
}
```

`validUntil` 为 `null`、空字符串或缺省时表示长期有效。冲突按 `handoffId + key` 分组；同组内有两个或以上活跃值且内容不同，即必须裁决。

也可以导入界面导出的 `{ "model": ..., "state": ... }`，以同时恢复裁决与上下文修改。

## 状态规则

- 可完成：必需上下文齐备且有效，外部依赖均处于可完成状态。
- 不完整：缺少必需上下文，但当前没有更严重的阻塞或不可信问题。
- 不可信：时效过期、缺失依赖、依赖成环，或上游不可信/不完整。
- 等待裁决：存在未处理来源冲突，或上游处于等待裁决。

完整度以 0 到 1 表示。自身完整度只统计该事项声明的必需上下文；链路完整度把外部前置事项作为同等重要的组成部分，环内共享同一 SCC 的上下文和外部依赖计算结果。

## 验证

```powershell
npm test
```

测试覆盖：

- 依赖链推导和四种状态；
- 冲突双方保留及裁决前阻塞；
- 缺失依赖与依赖成环显式报错；
- 过期上下文导致不可信；
- 修改上下文后增量重推范围正确；
- 增量结果与从头完整重推深度一致。
