# 预约-签到链路自动化验证

对服务端「注册登录 → 课程 → 预约 → 二维码签到核销」链路的外部可见行为做端到端验证。
全部通过 HTTP 调用真实服务端进程，不 mock、不直连内存存储；本地离线可重复执行。

## 运行

```bash
npm install   # 首次
npm test      # 运行全部用例（node:test，每个文件独立服务进程）
node --test tests/booking-risks.test.mjs   # 单独运行预约风险用例
node --test tests/checkin-risks.test.mjs   # 单独运行签到风险用例
```

## 覆盖的风险点

预约（tests/booking-risks.test.mjs）

- 并发预约容量有限课程：成功数 == 容量、无超卖、无同一用户重复占位
- 同一用户并发/重复提交相同预约：只产生一条有效记录，预约次数不重复累加
- VIP 优先：名额满时普通会员被拒、VIP 可订，VIP 预留名额（5 个）用完后同样被拒

签到（tests/checkin-risks.test.mjs）

- 有效凭证核销成功，预约状态同步为 checked-in
- 过期凭证、签名被篡改凭证：拒绝且预约状态不变
- 凭证归属其他用户 / 指向不存在预约：拒绝
- 同一凭证重复核销、并发核销：仅一次成功，其余拒绝，状态与结果一致

## 隔离与可重复性

- 每个测试文件启动独立的服务进程（随机端口），运行结束自动关闭
- 每个用例使用唯一邮箱注册、独立教练与新建课程，用例间不共享内存状态
- 单独执行与整体执行结论一致；过期/篡改/越权凭证通过测试内自签 token 构造，不依赖时间等待
