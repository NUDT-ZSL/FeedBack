# 交易/采矿结算 — 离线不变量验证

对 `src/managers/TradeManager.ts` 的核心结算逻辑做无浏览器、无网络的批量验证。
零新增依赖：利用 Node ≥22.18 的原生 TypeScript 类型擦除直接运行，
通过 `loader.mjs` 将 `phaser` 重定向到本地确定性桩 `phaser-shim.mjs`
（可设随机种子、可钉住下一次随机结果以注入边界值）。

## 运行

```bash
npm test                          # 默认: 种子1, fuzz 3 种子 x 500 步
npm test -- --seed=123            # 指定种子复现
npm test -- --fuzz-ops=5000 --fuzz-seeds=10   # 加大压力
```

退出码: `0` 全部不变量通过; `1` 存在失败或套件异常; `2` 参数错误。
失败报告按不变量编号分组，标注套件、触发场景与期望/实际值，可直接定位业务规则。

## 不变量目录

| 编号 | 规则 |
| --- | --- |
| INV-PRICE-01 | 波动/注册/重置后，各站价格 ∈ 基础价 [0.5, 2] 倍 |
| INV-CARGO-01 | 玩家库存总量 ≤ 货舱容量 |
| INV-CARGO-02 | 满舱时添加矿石，库存与累计开采量均不变 |
| INV-SELL-01 | 卖出前后，玩家+站点（及全系统）各矿物总量守恒 |
| INV-BUY-01 | 实际买入 = min(请求, 剩余舱位, 站点库存)；不静默吞掉、不凭空生成 |
| INV-BUY-02 | 无效买入（未知站点/矿物、非正数量、满舱）原样拒绝且状态不变 |
| INV-HIST-01 | 交易历史最多保留 10 条 |
| INV-HIST-02 | 历史按最近顺序保留（最新在前），超限丢弃最旧 |
| INV-HIST-03 | 每条记录 总价 = 数量 × 单价，且与对应交易一致 |
| INV-RESET-01 | 重置后库存/累计价值/累计开采量/交易计数归零 |
| INV-RESET-02 | 重置后站点库存与价格重新生成，价格仍满足 INV-PRICE-01 |
| INV-FUZZ-01..03 | 随机混合操作下：全局矿物守恒、站点库存非负整数、累计开采量记账一致 |

## 结构

- `run.ts` — 入口：参数解析、套件注册、报告与退出码
- `harness.ts` — 断言记录器与按不变量分组的报告器
- `loader.mjs` / `register.mjs` — ESM 钩子：phaser 重定向 + 无扩展名 `.ts` 解析
- `phaser-shim.mjs` — Phaser 离线桩（确定性 PRNG + 边界值注入钩子）
- `helpers.ts` — 公共构造/快照/区间校验工具
- `suites/` — 六个边界套件 + 正常路径冒烟 + 随机压力
