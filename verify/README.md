# 茶品收藏与品鉴笔记 · 离线批量验证体系

一条命令完成鉴权隔离、茶品/笔记联动、筛选分页、导出完整性的批量验证，
不依赖真实网络、外部账号或浏览器：运行器在本机随机端口启动一个 Express
实例（SQLite 使用 `/tmp` 下的临时库文件，跑完即删），四个套件依次跑在
同一实例上、靠固定且互不重名的用户样例互相隔离，请求全部走 `127.0.0.1`
回环地址，覆盖完整的 HTTP + 中间件 + SQL 链路。

## 运行方式

```bash
npm run verify
```

- 全部通过：退出码 `0`，输出各风险点 PASS 与汇总结论。
- 任一失败：退出码 `1`，失败项打印 `定位信息`（用户名、茶品/笔记标识、
  操作序号、预期值与实际值），可直接定位到触发不一致的具体对象。

## 覆盖的风险点

| 套件 | 内容 |
| --- | --- |
| 鉴权与用户隔离 | 重复注册/错误密码/缺参的状态码与错误文案稳定性；8 个接口缺失 `x-user-id` 一律 401；跨用户读/改/删茶品与笔记一律 404 且不污染数据；列表与导出不串用户 |
| 茶品与品鉴笔记联动 | 新增/修改/删除笔记后详情笔记列表与茶品列表 `avg_score` 同步；4 轮连续快速操作逐步核对，捕捉旧值残留；无笔记时平均分为 null |
| 筛选与分页边界 | 茶类、年份区间（含边界）、产地关键词、评分区间（单/双边界、组合）；每页条数、翻页并集（无漏算/多算/重复）与 `total` 均与固定样例逐条核对结果一致；无笔记茶品不参与评分筛选但在普通列表保留 |
| 导出内容完整性 | 含当前用户全部茶品（含无笔记茶品，笔记为空数组）、笔记挂接正确、不混入他人茶品或笔记、含 `export_date` |

## 目录结构

- `verify/run.ts`：统一入口，启动临时服务、依次执行套件、汇总报告、决定退出码。
- `verify/harness.ts`：临时服务生命周期（通过 `TEA_DB_PATH` 指定隔离库）、HTTP 封装、结果收集器。
- `verify/fixtures.ts`：固定样例数据（12 款跨 6 茶类/多年份/多产地、
  含 3 款无笔记茶品）与独立的 JS 参考实现（逐条核对基准）。
- `verify/suites/`：`auth.ts`、`linkage.ts`、`filters.ts`、`export.ts`。

## 服务端改动说明（为支持离线验证与修复发现的问题）

- `server/index.ts` 导出 `createApp(dbPath?)`，直接运行时行为不变；
  测试可对每个套件传入独立临时数据库。
- 修复列表接口两个缺陷：错误的 `LEFT JOIN ... ON t.tea_id = tn.id`
  （会导致列表请求直接失败）与 `COUNT(*)` 不携带筛选条件
  （筛选后 `total` 仍是全量数）；分页排序补充 `t.id` 作为稳定次序。
- 修复导出接口中文文件名直接写入 `Content-Disposition` 导致的 500
  （Node 头部只允许 Latin-1 字符），改为 RFC 5987 的 `filename*` 编码。
