# 语义约定（docs/semantics.md）

本文档是条件判定、回退、合并与存档迁移的**行为契约**。实现与测试均以本文为准。

## 1. 世界状态与变量

- 世界状态由一组**先声明后使用**的命名变量组成，每个变量有类型（`int` / `float` / `bool` / `str`）与缺省值。
- 类型规则：`bool` 不是 `int`；`float` 变量可接受 `int` 值（规范化为浮点）；其余类型不隐式转换。
- 状态变更操作：`set`（任意类型）、`add` / `sub` / `mul`（仅数值变量）。
- 进入节点时**按声明顺序**应用变更。任一变更失败（类型不符、引用未声明变量、对非数值变量做算术操作）时：
  - 该节点本次进入被**整体拒绝**，已应用的变更一并回滚，不留半应用状态；
  - 抛出的错误信息包含定位：节点标识 + 变更标识 + 变量名。
- 图在加载时做静态校验（`Graph.validate_against`），提前报告上述问题；运行期校验是最后一道防线，两者规则一致。

## 2. 条件求值

- 条件 = 变量与字面量比较（`eq/ne/lt/le/gt/ge`）+ 逻辑组合（`and/or/not`）+ 常量。
- **确定性**：求值是纯函数，不读时钟、不用随机数、不依赖迭代顺序；同一状态、同一条件，重复求值结果必然相同。
- **缺变量策略（重要，二选一并保持一致）**：
  - 变量**已声明**但当前状态中无值 → 使用其**声明的缺省值**参与比较；
  - 变量**未声明** → 该比较子句一律判 **False**，不抛异常，逻辑组合照常继续。
- 比较两边类型不可比较（如字符串与数字比大小）→ 判 False，不抛异常。

## 3. 回退与读档

- 每次成功进入节点前，引擎压入一份**完整快照**：世界状态、进度计数、已解锁集合、分支归属轨迹、变更日志长度、**汇合点状态（含冲突记录）**、当前节点。
- `rollback_to(node)` 恢复到该节点**进入前**的快照，并丢弃其后的全部历史——进度、解锁、分支归属、变更日志、汇合合并结果与冲突记录**一并回退，不残留后续痕迹**。
- 回退后重新走另一条路径，结果与首次到达时按相同规则推导一致（合并规则见第 5 节）。
- 存档包含快照历史，读档后仍可继续回退。

## 4. 分支归属

- 经带标签（`label`）的条件边进入节点时，记录 `[分叉节点, 边标签]` 到分支轨迹。
- 当前分支归属为轨迹的可读拼接，如 `n1:help>n3:spare`；无记录时为 `main`。

## 5. 汇合合并

两条路径在汇合节点相遇时，对各自累积的变更日志做确定性合并。路径通过
`arrive_at(汇合标识, 日志, 分支名)` 到达汇合点（`apply_merge` 等价于两条路径同时到达）。

1. **到达顺序无关**：合并结论只取决于各分支的日志与分支名。每次有路径到达，
   都对全部已到分支的日志**重新计算**合并结果，因此先到 / 后到不改变最终结论。
2. 同一变量被多条分支改成**不同的最终值** → 产生冲突：
   - **保留双方来源**（分支名、节点、变更标识、双方取值）；
   - 生成**可读冲突记录**，初始状态为未解决；
   - **未解决期间的生效值**：恒为分支名字典序最小一方的值。后到的一方不得
     覆盖先生效的一方；若后到者才是胜出方，生效值在到达时收敛到胜出值。
     任何时刻 `state[var] == 冲突记录.effective_value`，记录与状态自洽。
3. 未冲突的变量双方变更全部并入（多方写入同值时来源记为字典序最小分支）。
4. 冲突可通过 `resolve_conflict(variable, use_branch)` 显式解决；解决结果
   （采用值）在后续重算中保持，不会因新路径到达而丢失。
5. 可通过 `variable_status(var)` 查询某变量取值的可解释状态：
   `normal`（无冲突）/ `unresolved`（未决，标明值来自哪一分支）/ `resolved`。

## 6. 存档演进

- 存档携带 `format_version`（格式版本）与 `content_version`（内容版本）。
- **格式迁移**：`migration.MIGRATIONS` 登记逐版本迁移函数，`migrate_save` 沿链执行（v1→v2→…），不允许降级；缺迁移规则即报错。
- **内容演进**（`Engine.load` 时按当前 Schema/Graph 对齐）：
  - 存档缺少新版引入的变量 → 按迁移规则**补声明缺省值**，并记录迁移说明；
  - 存档引用新版中不存在的节点 → **标记为不可用**（`unavailable_nodes`），不删除历史；
  - 存档中存在新版已移除的变量 → 丢弃并记录；
  - **进度计数、已解锁集合、分支归属轨迹与迁移前完全一致**。
- 版本不符的存档必须先迁移再加载，否则拒绝。

## 7. 查询接口与稳定顺序

| 查询 | 接口 | 顺序保证 |
|---|---|---|
| 节点进入条件 | `entry_condition(node)` | 字段顺序固定的字典 |
| 某状态下可达后继 | `reachable_from(node, state=None)` | 按节点标识字典序 |
| 变量来源变更链 | `provenance(var)` | 按发生先后（日志顺序） |
| 当前分支归属 | `branch_attribution()` | 轨迹时间序 |
| 全部未解决冲突 | `unresolved_conflicts()` | 按变量名字典序，含生效值/来源分支/可读描述 |
| 变量取值状态 | `variable_status(var)` | normal / unresolved / resolved，标明来源 |

所有查询都是纯读取，重复调用结果一致。
