# 工坊状态一致性离线验证

针对「纹样合成 → 库存扣减 → 订单状态流转 → 撤销历史」链路的自动化验证，
纯本地运行：不访问网络、不依赖外部账号，数据全部来自本地夹具
（`scripts/verify/fixtures.ts`）。

## 运行

```bash
npm run verify
```

一条命令跑完全部验证，无需逐项手工执行。退出码为 0 表示全部通过；
任一场景失败或故障演练未被捕获时退出码为 1，并打印具体失败点。

## 验证内容

**[1/2] 边界场景**（`scripts/verify/scenarios.test.ts`，共 14 条）

- 合成原子性：扣料成功后、纹样提交前注入故障，不得留下已提交纹样或已扣库存；
  库存不足时提交，纹样与库存均不变；故障后同键可安全重试。
- 幂等性：相同幂等键连续提交只扣一次料、只留一条纹样；
  不同幂等键视为独立提交。
- 撤销：撤销后库存与纹样状态回到提交前，幂等键随之释放；空历史撤销安全返回。
- 订单流转：待制作 → 制作中途注入故障，不得出现「订单已流转而库存未扣」
  或「库存已扣而订单未流转」的单边结果；失败可重试；非法重复流转被拒绝。

故障注入点由领域层显式暴露（`StepOptions.failAt`），仅用于验证，
不需要 mock 框架或网络拦截。

**[2/2] 故障演练**（`scripts/verify/sabotage.ts`）

用 4 个被人为破坏的实现变体（不回滚、幂等失效、撤销不补偿、订单单边流转）
跑同一套场景，验证套件必须全部捕获；若有破坏未被捕获，本次验证整体判失败，
防止「验证本身失效却显示通过」。

## 目录

- `src/workshop/`：领域层（库存账本、撤销历史、工坊门面），被验证对象
- `scripts/verify/fixtures.ts`：本地样例（初始库存、纹样配方、订单）
- `scripts/verify/harness.ts`：极简断言与套件运行器，零依赖
- `scripts/verify/scenarios.test.ts`：边界场景
- `scripts/verify/sabotage.ts`：故障演练
- `scripts/verify/run.ts`：批量入口（`npm run verify`）
