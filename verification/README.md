# 日月食推演自动化验证

对日月食推演链路（输入参数 → 朔望定位 → 食分/食相 → 初亏·食甚·复圆时刻 → 可见区域判定 → 历代记录比对）做离线、可重复执行的批量验证。

## 运行方式

```bash
npm run verify          # 全量复核(编译 + 执行), 失败时退出码非 0
npm run verify:update   # 口径确认调整后, 按当前引擎重新固化基准数据
npm run eclipses:list   # 列出 1280-1380 年模型推演出的食象(选取新样例用)
```

- 执行阶段**完全离线**：不访问网络，不读取系统时钟，不使用随机数；同样输入永远得到同样结果。
- `npm install` 是唯一需要网络的一次性准备步骤；之后可离线反复运行。
- 编译产物位于 `verification/dist/`（已加入 .gitignore），运行时以仓库根为基准定位夹具与基准文件，从任何工作目录调用均可。

## 各套件验证内容

**boundary — 分界与临界**
- 日全食/日环食分界（d=0 时按月、日视半径大小定类）；全/环→偏食临界 `d = |Rm−Rs|`；偏食→无食临界 `d = Rs+Rm`，食分在临界处连续单调降至零；无食时无接触时刻。
- 月全食/月偏食/半影月食/无月食四层分界；接触弦长持续时长几何恒等式；正负黄纬对称。

**phases — 时刻状态一致性**
- 初亏 ≤ 食既 ≤ 食甚 ≤ 生光 ≤ 复圆（JD-UTC 与本地时间两套口径均单调），持续时长为正，偏食无食既/生光。
- 10 个时区（−12…+14，含半时区）切换不改变 UTC 时刻；本地时刻严格等于 UTC+偏移，跨日时年/月/日合法进位（样例含 UTC 23:15→大都次日 07:15）。
- ±89.5° 极区观测：全部时刻与高度角有界、无 NaN；极区初亏/复圆高度角差 < 0.5°（极昼/极夜稳定）。

**visibility — 可见性与食分自洽**
- 11×12 经纬网格（12 条样例 × 132 点）逐条用独立的高度角公式复算，必须与判定函数结论一致。
- 互斥规则：有效食分 ≤ 0 必定 `no_eclipse`；可见必定有效食分 > 0；有食必在地球某处可见，无食处处不可见。
- 注：食分达标但太阳/月亮位于地平线下时判 `below_horizon`（如日全食样例在 -180° 经度点），属于物理一致的"地面不可见"，不是口径矛盾。
- 对跖点高度角正弦和 ≈ 0；固定纬度沿经度扫描可见性最多翻转两次（无抖动矛盾）。

**records — 历代记录比对**
- 吻合（时辰 ≤2h 且食分 ≤0.1）、偏差（任一超阈）、无对应记录三类结论，与本地记录库逐一核对；偏差百分比按公式如实换算。

**golden — 全链路基准回归**
- 12 条固化样例覆盖：日全食（可见/地平线下）、日环食、日偏食、食分≈0.035 的临界偏食、无食、跨日偏食、月全食/偏食/半影月食/无月食。
- 食类、类型、中文名、食分（1e-6 容差）、各阶段时刻（1e-6 天容差）、阶段集合、可见性与原因全部对齐。

## 调整口径后的标准流程

1. 修改 `src/lib/astronomy/` 中的推演口径。
2. 运行 `npm run verify`：失败项会打印套件、检查名与实际/期望数值。
3. 若变化是有意调整，人工确认失败明细后运行 `npm run verify:update` 重写基准数据，再次 `npm run verify` 复核；`git diff verification/golden` 可直接审视每条样例的结论变化，避免口径"悄悄失真"。
4. 新增覆盖样例：在 `verification/golden/eclipse-cases.json` 增加输入（或用 `npm run eclipses:list` 挑选），执行一次 `verify:update` 固化期望结论；新增历史记录用例编辑 `verification/fixtures/historical-records.json` 并写定期望裁决。
